# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Vue d'ensemble

Pipeline Python (sans framework) qui lit les programmes des candidats à la présidentielle 2027, en extrait des propositions sourcées, les annote à l'aveugle par LLM (OpenRouter, questionnaire `q1`), calcule leurs positions par des formules publiques et produit un JSON lu par la constellation (`web/constellation_2027.html`). Le code est en français (docs, messages, identifiants de données). Guide d'exécution détaillé, source de vérité pour les options CLI : [docs/guide_pipeline_2027.md](docs/guide_pipeline_2027.md). Suivi du projet et décisions : [SUIVI_PROJET.md](SUIVI_PROJET.md).

Le dossier `upstream_repo/` est un **clone git d'un projet tiers** (`coucou123212321232123/presidentielle-2027-comparateur`, app React/Vite statique) : depuis le 2026-11-20 ce n'est plus qu'une **veille** : la chaîne lit les candidats, leurs liens de programme et les thèmes dans le registre local (`donnees/candidats_2027.json`, `donnees/themes_2027.json`, [registre_2027.py](registre_2027.py)), met le clone à jour par `git pull --ff-only` et liste ses écarts avec le registre sans rien appliquer (`registre plan`, `registre reprendre`). Il est ignoré par le dépôt ; ne pas y modifier de code. Spec des phases suivantes (veille des sites, flux, presse, circuit manuel BnF) : [docs/spec_veille_2027.md](docs/spec_veille_2027.md). [docs/audit_repo_presidentielle_2027.md](docs/audit_repo_presidentielle_2027.md) et [docs/presidentielle_2027_data_v2_structure.json](docs/presidentielle_2027_data_v2_structure.json) décrivent son bundle.

## Organisation

- Racine : `boussole_2027.py` (point d'entrée unique) et les modules actifs `*_2027.py`.
- `tests/` : tests ; `web/` : constellation et page du tableau de bord ; `docs/` : guide, spécifications, notes.
- `donnees/` : entrées versionnées (`candidats_2027.json`, `themes_2027.json`, `sources_surcharges.json`, `sources_2027.json`, `decisions_2027.json`) et sorties ignorées par git (`base_2027.json`, `donnees_interface_2027.json`, caches, états de batch, budget). Tous les chemins viennent de `boussole_2027.chemins()` (relatifs à `--racine`).
- `archives/` : ancienne chaîne (Jev puis seconde lecture, descripteurs, boucle de précision) dans `archives/code/`, anciennes pages, anciens résultats (`archives/donnees/`, dont `cache_scores.json`) et pilotes. Ne pas l'utiliser pour le pipeline courant.
- Dossiers de travail ignorés : `corpus_programmes/`, `logs/`, `runs/`, `sauvegardes/`, `planification/`.

# Constellation (la page et l'export, plus les sources et erreurs signalées par le public) : http://localhost:8000/

# Ne jamais servir le dossier avec « python -m http.server » : il publierait .env, les journaux et la base.

## Architecture

- [boussole_2027.py](boussole_2027.py) : orchestrateur (`plan`, `migrer`, `integrer`, `annoter`, `mise-a-jour`, `etape`, `decision`, `file`, `planifier`, `tableau-de-bord`, `votes`, `sauvegarder`) et `chemins()`.
- [base_2027.py](base_2027.py) : base unique (`donnees/base_2027.json`, uid stables `m-<candidat>-<n>`, versions, statuts), décisions humaines (`donnees/decisions_2027.json`, jamais écrasées par un run), calculs, file de validation, export, bilan, importance structurelle (sans LLM).
- [chaine_2027.py](chaine_2027.py) : chaîne complète (sources ajoutées, collecte et extraction via [update_corpus_2027.py](update_corpus_2027.py), intégration, annotation, compléments, étapes gratuites), plafonds par run et mensuel.
- [questionnaire_2027.py](questionnaire_2027.py) (questions, formules, idéologie), [annotation_2027.py](annotation_2027.py) (requêtes, cache, application), [descripteurs_2027.py](descripteurs_2027.py) (formule eco et vocabulaire repris par q1).
- [contexte_2027.py](contexte_2027.py) : méthode standard de notation, le questionnaire q1 lu avec le passage du document et le lexique (`annoter --contexte [--tous]`) ([lexique_2027.py](lexique_2027.py), `donnees/lexique_2027.json`) ; réponse « indéterminé » aux questions de sens (`Q.normaliser`).
- [decisions_2027.py](decisions_2027.py) : questionnaire q1 posé à un modèle de décision (API OpenRouter `/api/alpha/decisions`, par exemple `nace-ai/drex-max`) ; essai comparatif seulement, via `comparer_modeles_2027.py --candidat modele:decisions` (plan sans `--max-cost`) ; rien n'est appliqué à la base. Résultats : [docs/review_notation_2027.md](docs/review_notation_2027.md).
- [questionnaire_q2_2027.py](questionnaire_q2_2027.py) + [essai_q2_2027.py](essai_q2_2027.py) : questionnaire q2, **en production depuis la renotation complète du 2026-11-16** (base en `meta.questionnaire = "q2"` ; conditions oui/non par bloc, doublons retirés, axes institutions, alliances et défense, une seule règle de calcul) et son essai comparatif sur un échantillon figé, pour un modèle de texte (`modele:effort`) et des modèles de décision (`modele:decisions`) ; plan sans `--max-cost`, cache `donnees/cache_essai_q2_2027.json` (réécrit en entier par chaque processus : un seul essai à la fois ; retoucher une question oblige à tout relire). Étalons `donnees/etalons_q2_2027.json` (réponses attendues, à valider par l'utilisateur), échantillon neuf figé dans `runs/echantillon_q2_2027.json`, option `--groupes`. Lecture en production branchée : [lecture_q2_2027.py](lecture_q2_2027.py) (`annoter --q2` : drex-max puis pplx-decider lisent tout ; [arbitrage_q2_2027.py](arbitrage_q2_2027.py) : Terra reçoit les litiges de `Q2.motifs_arbitrage` avec les deux lectures A/B anonymes et leurs probabilités, choisit, donne confiance et raison ; dès qu'une lecture est appliquée, `base.meta.questionnaire = "q2"`, les lectures q1 s'arrêtent et la chaîne lit en q2). Méthode `essai-q2-v6` (réécriture du 2026-11-16) : les lectures payées en v5 se retrouvent par les textes figés `donnees/gel_q2_v5_2027.json` (ne pas modifier) ; une passe ciblée relit les seules questions réécrites (`L.QUESTIONS_CIBLE`) ; les lectures nouvelles ont le masquage enrichi (`commun_2027.masquer_alias`). Retoucher une question q2 change la clé v6 : prévoir une passe ciblée, et ne jamais changer les clés d'options (décodage des lectures en cache). `relecture_q2_2027.py evaluer` compare lectures et arbitre à la relecture humaine (gratuit). Aussi : `base_2027.appliquer_q2` calcule une annotation `version: "q2"`, l'export et la constellation affichent les axes `inst`/`inter`/`defense`, le financement et les indicateurs q2 seulement s'ils sont présents (export q1 inchangé). Note : [docs/questionnaire_q2_2027.md](docs/questionnaire_q2_2027.md).
- [registre_2027.py](registre_2027.py) : registre local des candidats et des thèmes (`charger` rend la forme de `adapt_v2_bundle`, lue par `update_corpus_2027.charger_donnees`) ; veille de l'amont (`veiller_amont`, écarts à identifiant stable, `donnees/veille_amont_2027.json`), reprise et refus journalisés. Les thèmes ne sont jamais repris de l'amont automatiquement (clé du cache d'extraction). Ajout d'un candidat absent de l'amont (`ajouter_candidat`, `origine: registre`). Retrait d'un candidat (`retrait`, statut `retire`, candidat soutenu ; exporté par `base_2027.statuts_du_registre`, masqué au départ dans la constellation). Recherche des programmes des autres déclarés dans `meta.other_declared[].programme_recherche`. Règle d'inclusion : un programme écrit pour l'élection de 2027 (pas celui d'une élection passée).
- [veille_2027.py](veille_2027.py) : veille des sites (phase 1) : flux `veille` des candidats du registre (RSS, sitemaps), relevé poli (robots.txt, une requête par seconde et par hôte), file de tri `donnees/veille_2027.json` (ignorée) reprise ou ignorée dans l'onglet Sources du tableau de bord (`veille_id` d'`ajouter_source`). YouTube non relevé (robots.txt).
- [rapprochement_2027.py](rapprochement_2027.py) : rapprochement des mesures d'un nouvel export (pré-tri gratuit, arbitrage LLM plafonné).
- [tableau_de_bord_2027.py](tableau_de_bord_2027.py) + `web/tableau_de_bord_2027.html` : tableau de bord local (127.0.0.1).
- [recherche_semantique_2027.py](recherche_semantique_2027.py) : recherche « Par le sens » de l'onglet Mesures, prototype de ce qui irait sur le VPS. Moteur principal : `qwen/qwen3-embedding-8b` par OpenRouter, clé dédiée et plafond mensuel lus dans `.env.recherche` (jamais `.env` ; modèle `.env.recherche.example`), dépense dans `donnees/budget_recherche_2027.json`, requêtes non journalisées ; seul appel payant possible depuis le tableau de bord. Index `donnees/index_recherche_2027.*` (`recherche_semantique_2027.py index [--max-cost X]`, reprend d'abord les vecteurs de l'essai). Secours (sans clé, panne, plafond) : modèle local Qwen3-Embedding-0.6B int8 en ONNX (`modeles/`, ignoré ; dépendances optionnelles onnxruntime, tokenizers), un texte à la fois (la quantification dynamique rend un vecteur dépendant du lot), index `donnees/index_recherche_local_2027.*` (`index --local`). Chaque moteur a son index, sa consigne et ses seuils (`Moteur`). Trouve un sujet, pas une position : les résultats sont rangés par les positions déjà calculées (`calculs.axes`). Les embeddings n'apportent rien au rapprochement (essai du 2026-11-21, `essai_embeddings_2027.py`, docs/suivi/09).
- [serveur_constellation_2027.py](serveur_constellation_2027.py) + `web/constellation_2027.html` : constellation et ses pages (`#avertissement`, `#methode`, `#coulisses` : note de méthode détaillée, chiffres recalculés depuis l'export et questionnaire q2 complet en annexe, `#sources`, `#contribuer`). Seules écritures, via [contributions_2027.py](contributions_2027.py), sans donnée personnelle, fichiers ignorés par git : `POST /api/contribution` (lien proposé, `donnees/contributions_2027.json` ; le tableau de bord, onglet Sources, le reprend dans « Ajouter un document » ou le refuse) et `POST /api/signalement` (erreur signalée sur une proposition depuis sa fiche, `donnees/signalements_2027.json` ; onglet Signalements et haut de la fiche d'une mesure : « Corrigé » ou « Écarter », un signalement ne modifie jamais la base par lui-même). Le récapitulatif des sources (`sources`, `sources_en_attente`, `meta.modeles`) est calculé à l'export depuis le manifeste du corpus ; un lien `file://` n'est jamais exporté.
- [commun_2027.py](commun_2027.py) : masquage des noms (annotation à l'aveugle), identifiant court, batch OpenRouter.
- [programme_corpus_2027.py](programme_corpus_2027.py) : sous-commandes `inventory/collect/reparse/ocr/extract/export`, dans `corpus_programmes/` (cache par empreinte : relancer ne repaie rien ; un document modifié invalide son extraction). Option `parcours` d'une source (`portee` arborescence|domaine, `profondeur`, `max_pages`, `exclure`) : `parcourir` découvre les pages HTML liées du même hôte, chacune devenant un document rattaché comme la page de départ ; les options ne sont pas dans le rattachement (`bindings_hash`), les activer ne relance aucune extraction. Collecte par navigateur : les hôtes listés dans `navigateur` de `donnees/sources_surcharges.json` passent par un navigateur Playwright ordinaire (classe `Navigateur`, dépendance optionnelle), qui passe le contrôle JavaScript anti-robot puis télécharge les octets avec ses cookies ; pas de navigateur furtif ni de falsification d'empreinte (CloakBrowser et camofox écartés le 2026-11-19).
- [pipeline_scoring_2027.py](pipeline_scoring_2027.py), [scoring_context_2027.py](scoring_context_2027.py), [export_interface_2027.py](export_interface_2027.py) : fonctions reprises par le pipeline (ingestion, champs dérivés, schéma des dimensions, requêtes HTTP, format compact de l'export). La CLI de `pipeline_scoring_2027.py` (scoring Jev) appartient à l'ancienne chaîne.
- [votes_2027.py](votes_2027.py) : votes parlementaires, phases 1 et 2. Phase 1 (`boussole_2027.py votes plan|chercher|votant|importer`) : import gratuit des scrutins officiels de l'Assemblée (`donnees/scrutins_2027.json`, ignoré) pour les votants déclarés (`donnees/votants_2027.json`, versionné). Seul accès réseau : l'archive officielle (hôte fixe, https, taille plafonnée) ; `--archive` et `--hors-ligne` n'en font aucun. Phase 2 : liens vote-mesure posés à la main dans l'onglet « Votes » du tableau de bord (classe `Donnees`, journal en ajout seulement `donnees/liens_votes_2027.json`, versionné, lié à la version de la mesure et au vote vu), exportés en `proposals[].votes` et affichés dans la fiche d'une proposition de la constellation (masqués en noms masqués). Les votes n'entrent ni dans la notation (aveugle) ni dans l'importance ni dans les positions ; ne pas les y brancher sans décision (spec §3, §6). Spec : [docs/spec_votes_2027.md](docs/spec_votes_2027.md).
- [llm_logging_2027.py](llm_logging_2027.py) : journal JSONL complet des appels dans `logs/` (clés masquées).
- [sauvegarde_2027.py](sauvegarde_2027.py) : `boussole_2027.py sauvegarder`, archive zip datée et relue (CRC, manifeste interne avec SHA-256 et commit) de `donnees/`, `corpus_programmes/` et `runs/` vers les destinations de `donnees/sauvegarde_2027.json` (ignoré par git ; ici E: puis copie sur le OneDrive personnel), rotation par destination ; lancée aussi en fin de `mise-a-jour --complet` (étape 6, `--sans-sauvegarde`, code 4 si elle échoue). Les données non versionnées n'ont pas d'autre copie hors du disque D:.

## Configuration

`.env` (chargé automatiquement, valeurs littérales, pas de commentaire en fin de ligne, ignoré par git ; modèle dans `.env.example`) : `OPENROUTER_API_KEY`, `OPENROUTER_SCORING_MODEL`, `OPENROUTER_WEB_MODEL`. Le modèle d'extraction de la chaîne est figé sur celui du corpus (changer : `--modele-extraction`). Ne jamais lire ni afficher `.env`.

## Règles et pièges non évidents

- **Aucun appel payant par défaut** : sans `--max-cost` (chaîne, annotation, intégration) ou `--max-calls` (corpus), tout est en plan. Ne les activer que sur demande explicite de l'utilisateur, avec un plafond.
- Un batch OpenRouter n'est pas annulable et réserve le pire cas (`max_tokens` dépend de l'effort).
- Les valeurs inconnues restent `null` (jamais 0) ; coût annuel chiffré uniquement à partir d'un montant explicitement annuel.
- Les citations extraites doivent être retrouvées textuellement dans les segments collectés ; l'OCR ne retient que les annotations du parseur (`type: file`), jamais la transcription du modèle.
- Les erreurs HTTP permanentes (400/401/402/403/404/422) arrêtent le run avec code 2 en conservant le cache.
- Les compléments du questionnaire sont hors `Q.QUESTIONS` pour garder la clé de cache des lectures payées ; ne pas y ajouter de question sans décision explicite.
- Ne pas écraser `archives/donnees/cache_scores.json` (cache Jev historique).
